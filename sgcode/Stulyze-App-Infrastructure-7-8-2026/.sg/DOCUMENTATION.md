# Global Settings Infrastructure — Terraform/OpenTofu Documentation

## 1. Overview

This Terraform configuration manages the core AWS networking and application infrastructure for the **global-settings** stack in region `ap-southeast-1` (Singapore). The code was generated by discovering live cloud resources, then imported into Terraform state, and reconciled until `terraform plan` showed **0 to add, 0 to change, 0 to destroy**, ensuring perfect alignment between code and live infrastructure.

**Reconciliation Status:** ✅ Clean — no drift detected.

The stack provisions:
- A Virtual Private Cloud (VPC) with DNS support
- Three public subnets across three availability zones
- An Internet Gateway for public egress
- A default security group with standard inbound/outbound rules
- A route table directing all outbound traffic through the Internet Gateway
- A Network ACL managing egress and ingress at the subnet level
- An AWS Athena workgroup for SQL query execution on S3 data
- A CloudFormation stack deploying the **stulyze-app** application

All resources are managed as imported state; no resources are left in a manual/drift state.

```bash
"$1" import -var-file environments/sg.tfvars 'module.security_group["default"].aws_security_group.this' 'sg-0b58b33cabde6d297'
"$1" import -var-file environments/sg.tfvars 'module.subnet["aws_subnet_1"].aws_subnet.this' 'subnet-0aec9ccc3d679b626'
```

Each line maps a Terraform resource address to its AWS resource ID:
- **`$1`** — the Terraform binary path (e.g., `/tmp/tmp.JanLil/terraform`)
- **`-var-file environments/sg.tfvars`** — loads environment-specific variables
- **First argument** — Terraform resource address (module path + resource type + name)
- **Second argument** — cloud resource ID (varies by resource type; e.g., AWS resource IDs, ARNs, names)


## 8. Notable Decisions & Caveats

### Resource Decomposition & Design Choices

1. **Default Network ACL (`aws_default_network_acl`):**
   - Uses `aws_default_network_acl` resource (not `aws_network_acl`) per Terraform AWS provider requirement for managing default ACLs created automatically by AWS.
   - The `default_network_acl_id` must be hardcoded in variables (e.g., `acl-0b1b4715940488f98`) and discovered from the live VPC; Terraform cannot create it.
   - Default deny rules (rule 32767 for ingress and egress) are automatically created by AWS and fall outside the 1–32766 valid rule number range; they are omitted from Terraform configuration but remain in the live ACL.

2. **VPC DNS Configuration:**
   - `vpc_enable_dns_hostnames` is set to `true` in `environments/sg.tfvars` despite the default being `false`. This matches the live VPC state discovered during resource discovery and is intentional for DNS hostname resolution support.

3. **CloudFormation Stack Lifecycle:**
   - The `cloudformation_stack` module includes `lifecycle { ignore_changes = [template_body, template_url, parameters] }`.
   - This is deliberate: the **stulyze-app** stack was deployed via AWS CLI (not Terraform), so its template body and parameters are not tracked by Terraform. Without `ignore_changes`, Terraform would detect a perpetual diff and attempt to recreate the stack on every plan/apply, causing unnecessary drift.
   - Users must update the stack outside Terraform or manually edit state if changes are needed.

4. **Route Table Association:**
   - The route table is defined in Terraform but not explicitly associated with subnets via `aws_route_table_association` resources. The route table is associated with subnets in the live infrastructure (likely via the AWS default route table or manual attachment); Terraform configuration does not enforce this association, so no `aws_route_table_association` resources are present.

5. **Security Group Rules (Dynamic):**
   - Ingress and egress rules are defined using `dynamic` blocks within the security group resource, not as separate `aws_security_group_rule` resources.
   - This simplifies management and prevents orphaned rules, but means all rules must be provided at once; incremental rule additions require re-applying the entire security group.
